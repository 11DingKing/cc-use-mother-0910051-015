# 文化遗产开放日排班服务

本项目是使用 Python、FastAPI 与 SQLite 实现的服务端应用，覆盖活动、场次、讲解员、主题、排班、评价、变更、预警和统计。它可在单个 Linux 应用容器内完成安装、测试、编译和接口验收，不依赖浏览器、外部数据库、缓存、消息队列或额外运行服务。

## 安装

```bash
python3 -m pip install -r requirements.txt -r requirements-dev.txt
```

## 测试

```bash
python3 -m pytest -q
```

## 编译

```bash
python3 -m compileall -q .
```

## 接口验收

```bash
python3 -c "from app.main import app; assert len(app.routes) > 5; print(len(app.routes))"
```

## 启动

```bash
uvicorn app.main:app --host 0.0.0.0 --port 8000
```

## 团体申请容量分配与候补递补

热门研学日学校报名人数可能超过单场容量，系统在 `/api/group-applications` 下提供
可追踪的容量分配：

- **原子拆分**：按学校的有序时间偏好、最小成团人数与同行约束（同行者不拆到时间重叠
  场次），一次报名可拆到多个场次；每片都不小于最小成团人数，且不给候补留碎尾。
- **确认前不锁定**：拆分结果是"待确认"软预留，只有学校确认（支持部分接受）后才转为
  正式占用，讲解员排班与场地容量据此锁定。
- **有序候补**：放不下的人数进入全局候补队列，排队序号 `seq` 即顺序依据；容量释放时
  在同一写事务内按"序号 + 当前资格"（意向含本场、时间不冲突、放得下且不留碎尾）
  原子递补，不符合资格的团队跳过并在事件流中说明原因。
- **守恒保证**：学校缩减人数、部分接受、超时未确认、退出单场、场次跨场取消都保持
  `申请总人数 = 各场有效占用 + 候补剩余人数`（终态申请全部核销为 0），服务层在每次
  变更后强校验，不守恒则整笔回滚。
- **原因可追踪**：每次拆分、确认、递补、跳过、缩减、过期、取消都写审计事件，含文字
  原因与守恒快照；`GET /api/group-applications/{id}` 可逐条追溯。
- **超时处理**：`POST /api/group-applications/waitlist/expire-overdue` 扫描超时未确认
  申请（建议定时调用），从未确认过的申请整体过期，部分确认申请的超时明细退回候补。

详见 `test_group_allocation.py`（覆盖拆分、确认、候补顺序递补、碎尾跳过、缩减、部分
接受、超时、跨场取消、并发不超卖等端到端场景）。
